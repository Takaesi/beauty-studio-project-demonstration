# Maison Lumière — сайт студии красоты с онлайн-записью

Клиент выбирает услугу, мастера и время, а администратор управляет записями и расписанием. Я описал пользовательские сценарии и правила доступности, спроектировал модель данных и реализовал запись, перенос и отмену визита.

**[Открыть демо с тестовыми данными](https://maison-lumiere-yw9l.onrender.com)** · [Критерий приёмки и проверка бронирования](#как-проверить-защиту-от-двойной-записи)

## Стек
Next.js 15 (App Router, Server Actions) · TypeScript · Tailwind CSS 4 · PostgreSQL + Prisma 6 · Vitest · Playwright.
Шрифты (Cormorant Garamond, Manrope) хранятся локально через @fontsource.

## Запуск
```bash
npm install
cp .env.example .env          # указать DATABASE_URL и пароль администратора
npx prisma migrate dev        # создать таблицы
npm run db:seed               # демо-данные (ОЧИЩАЕТ базу)
npm run dev                   # http://localhost:3000
```
Админка: http://localhost:3000/admin (логин/пароль — `ADMIN_LOGIN` / `ADMIN_PASSWORD` из `.env`).

## Как проверить защиту от двойной записи

**Требование.** Один мастер может обслуживать только одного клиента в каждый момент времени.

**Критерий приёмки.** Если два клиента выбрали один свободный слот одного мастера и практически одновременно подтвердили запись, система создаёт одну запись. Второму клиенту она сообщает, что слот занят, и предлагает выбрать другое время.

**Реализация.** [Расчёт слотов](src/lib/slots.ts) определяет, помещается ли услуга между соседними записями. При подтверждении [серверная транзакция](src/lib/booking.ts) блокирует конкурентные операции для этого мастера, повторно проверяет доступность и только затем создаёт запись. [Модель Booking](prisma/schema.prisma) хранит время начала и окончания.

**Ручная проверка.** На локальной копии с демо-данными откройте два независимых сеанса, войдите под разными клиентами и выберите одного мастера, услугу и слот. Подтвердите обе записи и проверьте расписание в админке. Для этого мастера и времени должна появиться одна запись. После обновления страницы второй клиент должен видеть актуальные свободные слоты.

В публичной копии доступен сценарий ручной проверки. Файлы тестов Vitest и Playwright в репозиторий не включены.

## Как устроено
- **Клиент**: регистрация и вход по телефону + паролю; запись возможна только из личного кабинета.
  В кабинете — предстоящие визиты, перенос, отмена, история.
- **Расчёт слотов** — `src/lib/slots.ts`: 14 дней, шаг 30 минут, не ближе чем за 2 часа,
  услуга должна закончиться до следующей записи и конца рабочего дня.
- **Двойная запись** исключена: создание/перенос идут в транзакции с блокировкой по мастеру
  (`pg_advisory_xact_lock`), свободность проверяется повторно внутри транзакции.
- **Цена и длительность** фиксируются в записи на момент бронирования.
- **Админка** (`/admin`): записи на день по мастерам (таймлайн + список), запись по телефону,
  перенос/отмена, график мастеров (шаблон недели → заполнение периода → правка отдельных дней),
  мастера (фото, услуги, скрытие), услуги (цена, длительность, мастера, скрытие), клиенты.
- **Фото мастеров** сохраняются в `uploads/` и отдаются по `/media/...`.
- **Время салона** — Москва (UTC+3), задаётся `SALON_UTC_OFFSET_MIN`.

- Карта в блоке контактов.
- SMS-напоминания (US-07) и подтверждение телефона по SMS — не реализованы.
